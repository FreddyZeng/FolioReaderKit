# FolioReaderKit

ePub reader/parser framework for iOS (Swift). Modernized fork: SPM-first, async/await parsing, dependency-injected persistence, local `GCDWebServer` to serve EPUB assets over `http://localhost` (works around `WKWebView` `file://` restrictions).

## Build & test

- Toolchain: `swift-tools-version:5.3` (Package.swift:1). Targets iOS 13+ / macOS 11+.
- Build/test the framework (no Xcode project for the lib itself — only the SPM target):
  ```bash
  swift build
  swift test
  ```
  Tests are defined under `Tests/FolioReaderKitTests/` and are wired up in `Package.swift:40`. Test-only mocks live in `MockHelpers.swift`.
- Example app is an Xcode project, not SPM: `Example/Example.xcodeproj` (no workspace). Open it directly in Xcode; it has multiple schemes (Example, MultipleInstances-Example, Storyboard-Example) in subfolders. The `Example` source files live in `Example/Example/`, `Example/MultipleInstances-Example/`, `Example/Storyboard-Example/`. There is no `pod install` step — the example links the local SPM package.
- Docs are generated by Jazzy (see `.jazzy.yaml`); output goes to `docs/`. `FolioReaderKit.xcodeproj` referenced in `.jazzy.yaml` no longer exists at the repo root.

## Dependencies (SPM, see Package.swift:13)

`AEXML`, `FontBlaster`, `MenuItemKit`, `SwiftSoup`, `ReadiumZIPFoundation`, `ReadiumGCDWebServer` (readium forks — note they are imported as `import ReadiumGCDWebServer` and `import ReadiumZIPFoundation`, not the upstream names). Pinned versions in `Package.resolved`.

`FolioReaderKit.podspec` exists for legacy CocoaPods consumers but is not the active distribution path — prefer SPM.

## Architecture entrypoints

- `Sources/FolioReaderKit/FolioReaderKit.swift` — top-level `FolioReader` class; `presentReader(...)` and `prepareReader(...)` are the public entry points (FolioReaderKit.swift:200, 209).
- `Sources/FolioReaderKit/FolioReaderContainer.swift` — host `UIViewController`; receives the `ReadiumGCDWebServer` instance and starts it on port `46436` (FolioReaderContainer.swift:34).
- `Sources/FolioReaderKit/FolioReaderConfig.swift` — configuration.
- `Sources/FolioReaderKit/EPUBCore/` — ePub parsing (`FREpubParserArchive`, `FRBook`, `FRSpine`, `FRSmils`, `FRMetadata`).
- `Sources/FolioReaderKit/Center/` — reader UI (view controllers, menus, list views, layout, sharing).
- `Sources/FolioReaderKit/Page/FolioReaderPage*.swift` — page rendering + `WKWebView` + JS bridge.
- `Sources/FolioReaderKit/Models/` — `FolioReaderHighlight`, `FolioReaderReadPosition`, `FolioReaderBookmark`, `FolioReaderFont`.
- `Sources/FolioReaderKit/Providers/` — provider protocols (see below).
- `Sources/FolioReaderKit/Resources/` — bundled `Bridge.js`, `Style.css`, `readium-cfi.umd.js`, `Images.xcassets` (referenced from `FolioReaderScript.swift`).

## Persistence is plug-in (no Realm in the modernized fork)

Users MUST supply provider implementations via `FolioReaderDelegate` callbacks, otherwise settings/highlights/etc. silently fall back to no-ops / in-memory defaults. The protocols:

- `FolioReaderPreferenceProvider` — settings (font, theme, scroll direction, margins, …). `FolioReaderDummyPreferenceProvider` (Providers/FolioReaderPreferenceProvider.swift:25) is a no-op base; `Example/Example/ViewController.swift:134` shows a `UserDefaults`-backed example.
- `FolioReaderHighlightProvider`
- `FolioReaderBookmarkProvider`
- `FolioReaderReadPositionProvider`

If you change one of these protocols, update the example implementations (`FolioReaderUserDefaultsPreferenceProvider`, `FolioReaderInMemoryHighlightProvider` in `Example/Example/ViewController.swift`) and the mocks in `Tests/FolioReaderKitTests/MockHelpers.swift`.

## Required init change vs. older docs

`FolioReader.presentReader(...)` and `FolioReaderContainer.init(...)` take a `webServer: ReadiumGCDWebServer` parameter (FolioReaderKit.swift:200, FolioReaderContainer.swift:46). The example passes `ReadiumGCDWebServer()`; the container's own fallback `self.webServer = ReadiumGCDWebServer()` at FolioReaderContainer.swift:73 means you can pass any instance but one is required. Do not "simplify" these signatures away.

## Async parsing

`FREpubParserArchive.parseCoverImage(_:)` is `async throws` and uses `ReadiumZIPFoundation` (`Archive`). Use `Task { ... }` to call it off the main thread (see Example/Example/ViewController.swift:78-87).

## JS bridge

`EpubJSBridge` (Sources/FolioReaderKit/EpubJSBridge.swift) parses `WKScriptMessage` payloads like `"<commandName> <body>"` and dispatches via `EpubJSBridgeDelegate`. Tests use `MockWKScriptMessage`/`MockScriptMessageHandler` in `MockHelpers.swift` to inject messages without a real `WKWebView`.

## Conventions / gotchas

- Public API style: `open` classes with `public` initializers. Many config-style enums have deliberately misspelled cases (e.g. `FolioReaderScrollDirection.horitonzalWithPagedContent` — FolioReaderConfig.swift:21) and a `styleOverride.rawValue`-based DSL in `FolioReaderKit.swift:771` (`CssLevels`, `CssImgLevels`). Don't rename without searching all call sites.
- `FolioReaderError` is the single error type thrown by the parser (FolioReaderKit.swift:22).
- `FolioReader.isReaderOpen` and `FolioReader.isReaderReady` guard `saveReaderState` (FolioReaderKit.swift:664); the reader auto-saves via `UIApplication.willResignActiveNotification` and `willTerminateNotification` observers.
- `.gemini/` is git-ignored and holds local tool artifacts (settings, prompts) — do not commit.
- `Sources/FolioReaderKit/FolioReaderKit.h` is the legacy umbrella header kept for the podspec; it is not part of the SPM target.
- `Example/Example/ViewController.swift` mixes storyboard IBActions with the integration glue; treat it as the canonical usage example.

## Lint / format

No SwiftLint, SwiftFormat, or other linter is configured. There is no CI workflow in `.github/` (only issue templates). Run `swift test` to validate.
